# the original game: full parity audit, 2026-10-14

**Latest follow-up: [independent Gemini work review](GEMINI_WORK_REVIEW_2026-10-14.md).** This document preserves the earlier audit snapshot. The latest review and scorecard supersede its working-tree counts/test results; current selected counts are 59 retained bounded matches, 18 known differences and 22 unresolved.

**Verdict: the rewrite does not have 1:1 parity. The previous “100% closure” and “zero known differences” claims are unsupported.** There are substantial differences in the production animation, gameplay, camera and front-end paths. A native-looking asset, a recovered arithmetic helper, or a passing rewrite test does not establish equivalent game behavior.

This audit reviews every existing parity obligation, checks integration in the running game, expands missing coverage, and identifies 30 findings below. It is a comprehensive gap audit, not certification that every original state, animation or screen has been compared. Full paired runtime, framebuffer and audio validation remains open. No whole-game accuracy percentage is justified.

The corrected selected inventory has **99 active obligations: 56 retained bounded matches, 21 known differences and 22 untested/unresolved**, plus one user-deferred item. 34 previously closed claims were reopened and nine missing runtime obligations were added. The [per-case review](PARITY_CASE_REVIEW_2026-10-14.md) accounts for all 100 entries.

## Prioritized findings

“Difference” means an observed code/integration or visual defect. “Open” means the stated parity claim lacks adequate comparison evidence. P1 findings block a credible original-game experience; P2 findings affect fidelity or verification. Finding IDs are stable references in the corrected manifests.

### Animation and movement

**F03 — P1, difference: the recovered ordinary VM is not the live actor driver.** `ordinary::update_primary`, `apply_effects` and `OrdinaryActorSink` have definitions and test uses, but the match does not execute this effect stream to drive actor poses, root motion and callbacks. `Player::step` still runs the generic action state machine. A callback interface and a test sink are not production integration. Sources: [ordinary.rs](../crates/street-sim/src/ordinary.rs), [player.rs](../crates/street-sim/src/player.rs).

**F04 — P1, difference: native input and gait helpers are disconnected.** `dpad_magnitude`, `combine_input_intensity`, `evaluate_gait_family_hysteresis`, `compute_physical_motion`, `native_velocity_step` and `ButtonEdges` are defined/exported and tested, but not consumed by the live movement path. Live controls quantize sticks to ±127; `Player::walk` chooses walk/run/turbo through generic thresholds, acceleration and turn limits. Native analog hysteresis depends on current record flags and intensity bands 40/59, 39/61 and 41/60; turbo is a separate physical-speed multiplier. Sources: [input.rs](../crates/street-sim/src/input.rs), [controls.rs](../crates/street-game/src/controls.rs), `player.rs:603`, `SIM_RECOVERY.md` “Gait family hysteresis and physical producer”.

**F05 — P1, difference: the new gait channel does not synchronize locomotion and display.** `PlayerGaitChannel::update` selects only rows 65/88/89, uses a fixed root distance `0.366667`, receives body scale **1.0**, and advances position with host sine/cosine. The original runtime table has 108 records, differing root distances, category/player restrictions, motion ranges and flags. The original record at `0x4b97d0`, for example, has row alternatives 88/89 and root distance about `0.590390`, not the hard-coded value. `sync_players` does not read the player's gait row/phase; it independently selects clip constants and rate clamps. The result can be foot sliding and incorrect stride/turn transitions. Sources: `ordinary.rs:464`, `player.rs:646`, `view.rs:1010`, native gait table and `native-shot-gait-raw.txt`.

**F06 — P1, difference: actions are timer-driven rather than callback-driven.** Ordinary shot release is 0.9 s, dunk contact 0.65 s, pass recovery 0.35 s, swipe 0.15 s and fakeout 0.25 s. Jump height is a synthetic parabola and dunk/layup travel is a generic easing curve. `sync_players` retimes clips independently using action duration and a playback speed clamp. Different equipped moves therefore share authoritative action timing while showing different clips. Sources: `lib.rs:100`, `player.rs:414`, `view.rs:804`, [clip.rs](../crates/street-game/src/clip.rs).

**F07 — P1, difference: an ordinary move script is flattened to one clip.** `script_selection` takes the first available blend target, then the first clip target as fallback. Its own comment says handed VM phases are not executed. Hand choices, later blends, waits, per-frame flags, root locks and callbacks cannot follow the full original script through this path. Same-clip actions also hit the animator's pointer-equality early return, so a new action can inherit an old clip frame instead of restarting. Sources: `clip.rs:328`, `animation.rs:432`.

**F08 — P1, difference: held-ball physics and visible attachment disagree.** The simulation carries a ball at waist height `3.0 + player.height` and forward offset 0.9. The renderer uses a hand for busy actions and a cosine dribble for idle/moving possession. Standing dribble phase uses elapsed display time. Only flag mask 4 selects the left hand; mask 12 falls into the right-hand branch rather than expressing the native both-hand behavior. Captured blend offsets and native dribble/special attachment branches are not executed by this display path. A single-hand attachment helper can be correct while the live ball path is wrong. Sources: `ball.rs:178`, `view.rs:1170`, `native-core-functions.json / FUN_0014da20`, original recovery notes.

**F09 — P1, difference: self-toss target and timing are placeholders.** Script 69 uses the fixed captured-looking local offset `[4.1959, 3.7131, -1.1863]`; every other self-toss script uses `[1.0, 3.5, 2.0]`. These are not destinations sampled from the player's current authored rig/model/heading/planner state. `Player::step` applies script 69's 54-update duration and update-20 launch to all six self-toss scripts. Sources: `self_toss.rs:7`, `self_toss.rs:36`, `player.rs:517`, `lib.rs:1071`.

**F10 — P1, difference: equipped bounce toss and native catches are not wired.** Callback 53's bounce solver exists, but `World::self_toss_launch` calls the ordinary direct `ball.throw` for every script, including bounce script 23. `step_pass` allows self-target passes to bypass both horizontal and vertical catch checks once flight time ends. Native collision/catch-ready and trailing-timeout behavior is materially richer. Sources: `self_toss.rs:103`, `lib.rs:1071`, `passing.rs:419`, `SIM_RECOVERY.md` callback-53/collision chain; `native-continuations.json`.

**F24 — P1, open: complete fractional/body/facial pose parity was never established.** The “complete” entry cites an offline main-hierarchy reconstruction with 16,663/16,758 position matches and 16,660/16,758 quaternion matches. It excludes head 21 and auxiliary bones 22..42. A separate fractional comparison is 6,454/10,142 within 1e-4, excludes blends and has large retained errors. These datasets are not full current production pose comparisons. Source: retained original reports referenced by `gameplay.complete_fractional_pose`; `animation.rs:490`. Do not convert these percentages into whole-game accuracy or attribute every residual to the rewrite without resolving capture alignment.

**F25 — P1, open: staged hand agreement is being mistaken for original sequence parity.** Disc tests for all 16 plans validate internal plan/clip/hand agreement and terminal scoring; millions of comparisons between two rewrite consumers do not compare millions of original observations. The retained scalar-corrected GamLR3 report still has 3/1,701 phase/counter nonmatches and the intro report 1/2,145. Captures cover selected scripts/actors, not every original execution of all 16 sequences. Their read timing and frozen source hashes limit attribution to the current tree. Source: `staged.rs` tests, `scalar-fix-report-results.json`, `SIM_RECOVERY.md`.

### Gameplay

**F11 — P1, difference: AI remains a custom streetball policy.** `ai.rs` explicitly describes its simple plan. It uses stateless SplitMix-derived dice, fixed spacing spots, slot-to-slot marking, hand-authored probabilities, and generic drive/pass/shoot thresholds. Recovered difficulty/meter constants do not turn this policy into the original AI play/actor state machines. Source: [ai.rs](../crates/street-sim/src/ai.rs).

**F12 — P1, open: correct RNG algorithm does not establish gameplay draw-order parity.** The six-word generator has independent bounded original evidence. The full caller-order obligation remains unverified because actions, reactions and AI are different, and AI deliberately avoids the world's RNG. Identical initial seeds therefore do not establish identical gameplay decisions. Sources: `rng.rs`, `ai.rs`, `street.rs`, `gameplay.gameplay_rng` limitations.

**F13 — P1, difference: shot-quality contest logic is demonstrably mistranslated.** Native `FUN_001805e8` subtracts the result of `FUN_001801e0`, which can return 0/1/2; the <14 penalty is conditional on a nonzero result. It then performs another defender search and additional <8/angle penalties. Rust uses one nearest distance, a boolean “in front”, and an unconditional <14 decrement. Native contest evaluation also includes heights, blocks and a quantized angle, not just an XZ dot product. Original raw `0x1809a8` branches over the <14 block when result is zero. Sources: `shooting.rs:336`, `lib.rs:701`, native exports and `native-shot-gait-raw.txt`. This changes shot tiers in ordinary play.

**F14 — P1, difference: shot outcomes and collisions are still a simplified model.** Hit chance is the hand-authored `0.15 + 0.10*tier`, fade -0.08 and GB1 +0.30 mapping. A make/miss is chosen at release, stored in `Shot::made`, and scored on timer expiry; dunks/oops can score directly at their generic action moment. Native rim/backboard/net geometry constants were added/exported but are not consumed by the live ball collision path. A correct free-flight integrator does not close rim, board, block, goaltend or rebound behavior. Sources: `shooting.rs:307`, `shooting.rs:418`, `lib.rs:651`, `lib.rs:782`, `lib.rs:1096`, `ball.rs:189`.

**F15 — P1, difference: passing is not driven by the recovered pass records.** `throw` launches immediately when the action starts, from fixed height 4.8, using generic speed 42 and two iterations of receiver leading. It writes a native kind number without consuming the native 28-byte pass records' trajectory/release/catch rules. Interception is one distance/height attempt at chance `0.25 + 0.45*steals`; catches occur at timer expiry with generic reach checks. Sources: `passing.rs:142`, `passing.rs:325`, `SIM_RECOVERY.md` pass/catch trace.

**F16 — P1, open: drain/combo event context is not verified in the live game.** Native ring arithmetic and a `DrainEventManager` exist, but production callers supply generic event/player data, including literal false gates and `score != 3000`. There is no paired native transition/ring log proving the full handler context. Do not treat a mocked manager test as equivalent notification ordering. Sources: `combo.rs`, `World::swat` / `swipe`, `passing.rs:325`, `gameplay.drain_combo_event_context`.

**F17 — P2, integration gap: formation recovery is disconnected.** `restart_formation` has only test callers in the Rust tree. Normal `inbound` teleports one nearest player to a baseline spot and leaves other placement to the custom AI. The recovered six-player reset must be tied to its exact native triggers before claiming restart parity; this finding does not assume every dead ball should use that reset. Sources: `lib.rs:1013`, `lib.rs:1045`, `tests.rs:1644`, `ordinary.rs` formation data.

### Camera and GUI

**F18 — P1, difference: camera recurrence runs per displayed frame.** `GamePlugin` schedules `follow_camera` in `Update`; it ignores time and advances the row helper, positioned easing and blend counter once per invocation. Simulation ticks run in `FixedUpdate`. At 30/60/144 display updates per second the same native recurrence gets different numbers of updates. Pausing does not gate this camera update schedule either. Sources: `game.rs:262`, `view.rs:1348`, `CameraManager::update`. Correct arithmetic helpers do not fix this timing defect.

**F19 — P1, difference: camera selection and lens state are simplified.** `Control.demo` always selects a positioned camera initialized to a fixed eye and distance scale; the native event-selected/randomized positioning path is not reproduced. The row helper gets fixed flags 0x40; row FOV comes from a constant mode mapping rather than consuming all controller state. The source adapter suppresses motion for every busy action and lacks the native channel/root descriptor inputs. Widescreen unconditionally substitutes the mode FOV, even when an authored staged camera supplies its own FOV. Sources: `view.rs:428`, `view.rs:476`, `view.rs:1319`, `view.rs:1348`, `CAMERA_RECOVERY.md`. Native helper presence is not full manager parity.

**F20 — P1, visible defect: Main Menu rows overlap its footer.** The fresh Main Menu image shows Online over the help area and Controls over the footer/bottom edge. The menu supplies more rows than the authored entries, and `look::build` reuses/extrapolates the final entry's coordinates. The added online feature is outside original parity, but its layout visibly damages the shared screen. Sources: `look.rs:981`, `menu.rs:3020`, [rewrite-main.png]($EVIDENCE/street-full-parity-audit-20261014/rewrite-main.png).

**F21 — P1, difference: the front end still uses generic widgets/screens.** Only selected pages receive `Style::Screen`; most use a synthetic `Style::List` with calculated font fitting, split-string columns, list scrolling and text markers. Native widget factories, list bindings, screen transitions and selection animation are not fully instantiated. `screen_step_filtered` supports availability in tests, but production `screen_step` passes `|_| true`. The menu graph mapping omits Main Menu and Play It even though drawing uses their authored screens; their navigation remains generic wrapping. Sources: `look.rs:694`, `look.rs:937`, `menu.rs:1327`, `menu.rs:3020`, `FRONTEND_RECOVERY.md`.

**F22 — P2, difference/open: GUI aspect, help wrapping and movie composition remain unverified.** `look::show` scales 640x480 coordinates to full-window percentages and stretches each image; the GUI is not attached to the 3D camera's 4:3 viewport. Menu help explicitly flattens authored line breaks. The Main Menu movie visibly overlays backdrop artwork in the current output, but no paired original frame proves the exact native composition. Options is still a generic scrolling list. Rectangular crop/loop-selection tests do not establish aspect, compositing, frame timing or whole-screen parity. Sources: `look.rs:1313`, `menu.rs:3006`, `movie_panel_rect`, [rewrite-options.png]($EVIDENCE/street-full-parity-audit-20261014/rewrite-options.png).

**F23 — P2, open: lighting, skinning and shadow output are not compared to the native renderer.** Players use Bevy `StandardMaterial` with guessed roughness 0.85 and reflectance 0.0; a directional-light orientation does not reproduce the native ToonShade/Skin program. Shadows use host skinning, modified sun directions, a 0.03 lift, per-triangle depth offsets and depth-write blending in place of the native GS destination-alpha behavior. No paired evaluated vertex/normal, coverage or pixel output verifies these choices. Sources: `player.rs:252`, `app.rs:150`, `shadow.rs:43`, `shadow.rs:147`, `shadow.rs:274`, `FORMATS.md`. The current Rucker screenshot is a smoke capture, not pixel proof.

### Audio, saves and verification

**F26 — P1, difference/open: the speech queue is not connected to playback.** `SpeechQueue` and its enqueue/pop functions have library tests but no game consumers. The game starts commentary directly in `say_file` and suppresses player requests through busy/cooldown checks. Two native blocking globals and all Script Manager states are not demonstrated by that simplified gate. Queue capacity/priority tests do not establish live request arbitration. Sources: `speech.rs:890`, `audio.rs:1024`, `sfx.rs:901`, native `FUN_001ad068`; F02 describes the current failing tests.

**F27 — P2, difference: speech randomness is only partly unified.** Move/block/steal selectors can share `Effects::speech_random`, but generic prefix commentary, song selection and some line selection still use `Sounds::roll`'s xorshift32. `Effects` also has other local chance gates. This is not a verified single native middleware draw sequence across all events. Sources: `audio.rs:386`, `audio.rs:835`, `audio.rs:1060`, `sfx.rs:917`. The 3,969 exact PLAY lookup keys remain useful bounded evidence; they do not compare the resulting mixed sound.

**F28 — P1, difference: original-save semantic completeness is false.** The importer walks ten original career records but stops creating usable stars when the six `BALLER_SLOTS` are full. Later careers without a `mapped_stars` entry are skipped by the semantic career import. The original bytes remain in a sidecar, but all ten original careers cannot be restored as equivalent playable state. No original-game continue/save/reload round trip proves full semantic equivalence. Sources: `original_save.rs:178`, `original_save.rs:187`, `original_save.rs:215`, `story.rs` slot constants. Distinguish byte retention from playable-state restoration.

**F29 — P2, open: ancillary presentation/replay coverage is missing.** Crowd selection uses a custom liveliness/random picker; nets use a host Verlet solver with chosen gravity/damping/iterations; ambience/effects, replay entry/exit and non-staged intro ball arcs have no comprehensive paired original/rewrite comparisons. Narrow asset decoding and authored net rest positions remain valuable. These missing runtime obligations have been added to the inventory rather than assumed closed. Sources: `crowd.rs:265`, `net.rs:29`, `ambience.rs`, `trails.rs`, `game.rs` replay, `view.rs` staged intro ball interpolation.

**F01 — P1, reporting defect: “100% closure” is not evidence.** Before this audit the scorecard regenerated 90/90 matches: 8 exact, 5 numerical, 77 structural. Several scenarios demand full game behavior or output while their limitations admit custom heuristics, absent comparisons, excluded bones, disconnected components or unresolved camera generations. For example, `audio.full_output_comparison` says continuous mixed PCM was not compared, and `presentation.gs_pixel_output` has no paired framebuffer evidence. These entries have been reopened; historical measurements are preserved.

**F02 — P1, verification defect: the current gate is not clean.** The fresh workspace run has two deterministic commentary test failures. The progress file's “all tests clean” assertion was removed. Repair the API/test contract and rerun the affected tests without turning this into an unsupported assertion that commentary is absent.

**F30 — P1, verification defect: the ledger validates evidence files, not truth or integration.** The reporter accepts manually supplied statuses; it verifies file presence and optional hashes but does not verify locators, ensure the claimed symbol exists/calls production, inspect result acceptance, or bind every frozen adapter result to the current binary. Some manifest notes refer to `SelfTossTimeline` execution that the production path does not perform. New helpers can pass implementation-shaped tests without being used by a match. Sources: `parity_scorecard.py:80`, capture test environment gates, `gameplay.script69_authority` pre-audit notes. The revised report remains an inventory, not an automatic parity oracle.

## Repair order and acceptance

1. **Restore an honest gate.** Fix F02's test/API disagreement; keep broad output obligations open and preserve every excluded/nonmatching observation. Do not repin evidence automatically to make the report green.
2. **Give ordinary actions one authoritative native clock.** Connect input/family/record selection, VM execution, root/heading state, poses and animation callbacks to both simulation and display. Remove fixed target/timer stand-ins from self-toss and pass/shot releases. This addresses F03–F10 and the animation/gameplay connection.
3. **Recover real gameplay decisions and contact state.** Translate shot-tier branches exactly, consume native collision/pass/catch data, recover AI/reaction/caller order, and compare per-tick events/RNG. Verify drain context and exact formation triggers.
4. **Correct camera scheduling and GUI composition.** Tick camera state at the native cadence, interpolate for presentation, preserve helper/lens transitions, and rebuild each screen from its runtime widget bindings. Fix visible overflow and compare matched 4:3 frames before widening.
5. **Close live audio and profile loss.** Connect the queue/gates/random sequence to playback; import every original career without sacrificing usable state. Then validate mixed output and original-save continuation.
6. **Use paired acceptance for closure.** Every broad obligation needs the same original/rewrite starting state, timed inputs, original observations, production output, declared tolerance and complete failures/exclusions. A field/table/helper match should remain narrowly named. Passing rewrite-vs-rewrite tests proves internal consistency only.

The corrected [parity scorecard](PARITY_SCORECARD.md) and its per-case inventory retain historical evidence, explicitly reopen unsupported claims and add missing runtime obligations. They must not be presented as a game-wide accuracy percentage.
